## 相对 v4 的变化

1. **子页面的外壳换成顶部胶囊（本轮最大改动）。** 原来四个子页面共用一条 54px 固定顶栏加一条 64px 底部通栏，站主觉得“太压”。现在顶部正中是一枚 46px 玻璃胶囊（`Spark Light` + 一颗缓慢自转的星），鼠标悬停或点一下才向下展开导航面板；底部改成左下角排单状态胶囊 + 右下角「下单与联系」。
2. **外壳形态由主题声明。** `themes/registry.js` 新增 `chrome: 'pill' | 'bar'`；`core/init.js` 在 `<head>` 里把结果写到 `<html data-chrome>`（避免内容先按旧边距排一遍再跳）；`core/shell.js` 按它搭结构。`t1-starfield` 用 `pill`；不写的主题仍然是原来的通栏 `bar`。
3. **主界面完全没动。** 主界面有自己的 `#folio` 顶栏与悬浮球导航，走 `data-shell-header="off"` 分支，本轮没有改；新的边距规则也把 `data-page="home"` 排除在外。
4. **AI 漫剧页与小游戏页按参考稿重做，并按站主反馈补齐。** 漫剧页是“放映厅”（银幕 + 胶片条 + 关灯放映）；小游戏页是“方块游戏机”（4×4 墨色方块 + 白色线描猫 + 预览夜景）。

7. **多主题的边界已经说清：** 每一套主题有自己的表现形式；`视觉原型/Spark Light 像素街机主题原型.html` 是**主题**原型（里面自带它的开屏），不是加载页原型。

## 硬性约束

以下规则贯穿所有页面和所有阶段，不可被设计偏好覆盖。

1. **禁止 emoji。** 页面可见文本、按钮、提示、占位文字里都不得出现。图标用 SVG 或纯文字符号。运行 `python3 tools/check_no_emoji.py`（会拦截对勾、星形等易被渲染成彩色的符号）。
2. **手机优先。** 先保证手机上流畅可用，再适配桌面。
3. **动效可降级。** 尊重系统“减少动态效果”，并提供“简化动效”开关。简化动效下由 `core/base.css` 的全局规则停掉动画与过渡，脚本里的动画要读 `data-motion`（统一用 `core/raf.js` 的 `isSimple()`）自行降级。
4. **多文件静态项目。** 无构建步骤，能直接放进 GitHub，由静态托管部署（方案待定）。
5. **内容与样式分离。** 价目、作品、须知、字卡、留言等内容只写一份，放在 `data/*.json`。
6. **每个页面是独立沙盒。** 自己的 HTML、`page.js`、`page.css`，页面之间不共享运行状态；一个页面或一个数据文件出错不影响其他。页面可以引用 `core/` 的共用模块，但不引用其他页面的代码。每个小游戏同理。
7. **不替站主决定。** 营业须知条款、退款规则、定位语、联系方式、业务介绍、AI 创作细则、授权说明原文等站主未提供的内容，只放清晰的占位，不自行编写，更不编造价格或承诺。
8. **不凭印象说外部事实。** 免费额度、平台规则、第三方服务限制必须现查并让站主确认。本文档“现查结果”只是 2026-11-22 至 2026-11-24 的记录，开工前涉及时要重新查。
9. **客人隐私与授权。** 展示客人的图、昵称、占卜内容前必须已获授权。`feedback.json` 只登记已获授权的内容。
10. **AI 内容如实标注。** AI 生成的作品，页面上如实标明（`ai: true`；漫剧页自动标注“本页内容由 AI 生成”）。
11. **所有可见文字用 `textContent` 写入。** 需要用 `innerHTML` 的地方，只能放写死的可信常量（图标 SVG、参考稿的线条插画等），数据必须先转义或改用 `textContent`。
12. **资源要能释放。** 漫剧播放器、图片、游戏的动画、计时器、音频、上传预览的临时地址，在访客关闭窗口、离开页面或切到后台时要及时释放。动画循环统一用 `core/raf.js` 的 `createLoop`，不要写常驻定时器。
13. **口令校验必须在后端。** 返图页的口令不得写在前端代码或数据文件里，也不得在前端比对。
14. **不提地域。** 文档、页面和文件里不要出现针对某个国家或地区的访问、速度、屏蔽之类的说法；默认访客在欧美地区。
15. **主界面不动。** 主界面的 `#folio` 顶栏、悬浮球导航、底部通栏，除站主明确要求外不要改。

### 外壳（本轮改动的重点）

- **两种形态，由主题声明。** `themes/registry.js` 的 `chrome: 'pill' | 'bar'`。`core/init.js` 把选中主题的 `chrome` 写到 `<html data-chrome>`，`core/shell.js` 读它决定搭哪套；主界面走 `data-shell-header="off"` 分支，永远用它自己的顶栏与悬浮球。
- **胶囊（`chrome: 'pill'`）。** `.sl-chrome`（固定、顶部居中、`z-index: var(--sl-z-chrome)` 60）里依次是：`.sl-nav-veil`（展开时的淡遮罩）、`.sl-pill-btn`（`Spark Light` + `.sl-pill-star`）、`.sl-nav-panel`（页面列表）。
  - 展开：悬停 120ms 后开、离开 220ms 后收（仅 `hover: hover` 且 `pointer: fine` 的设备）；点一下也能开关。
  - 关闭：Esc（焦点还给胶囊）、点遮罩、点面板外；Tab 在胶囊与面板里循环。
  - 内容来自 `data/site.json` 的 `nav`，当前页 `aria-current="page"` 带星并高亮；最下面“更多与设置”打开原来的星盘面板弹层（导航 + 章节快捷入口 + 简化动效 + 主题）。
- **底部（`chrome: 'pill'`）。** `.sl-dock`：左边 `.sl-dock-state`（排单状态胶囊，点开下单弹层）、右边 `.sl-dock-order`（下单与联系）。原来的 `.sl-orderbar` 通栏只在 `bar` 形态与主界面使用。
- **边距。** `html[data-chrome="pill"] body:not([data-page="home"])` 顶部 70px、底部按 `--sl-bar-h` 计算，保证内容不被胶囊与浮动按钮压住。
- **装饰归主题。** 结构在 `core/base.css`，星盘底、边光、小星、菱形分隔、当前行渐变在 `themes/t1-starfield/theme.css` 最后一节；其它主题不写就是干净的白面板。

### 关键机制

- **主题。** 访客选择存在 `localStorage` 的 `sl.theme`，动效选择存在 `sl.motion`。新增主题：建 `themes/<id>/theme.css`，在 `themes/registry.js` 加一行并把 `status` 改为 `ready`；需要专属页面皮肤就在 `pages` 里登记。
- **页面骨架。** 每页 `<html data-root="../" data-page="xxx">`，`<head>` 里按顺序放：字体 preload、`core/base.css`、`themes/registry.js`、`core/init.js`；`<body>` 末尾放 `core/boot.js` 与本页 `page.js`（均为 `type="module"`）。所有资源路径相对 `data-root`。
- **子页面样式隔离。** 作品页与返图页的选择器分别限定在 `.wkp`、`.fbp` 之下；漫剧页与游戏页限定在 `body[data-page="drama"|"games"]` 之下。全屏浮层外面套同名前缀的包裹层。关键帧名带 `drp-` / `gmp-` 前缀。
- **返图页。** `feedback/page.js` 读 `feedback.json` 与 `notice.json`，先建电话再等数据；`phone.js` 管拨盘与拨号声（默认关）；`memo.js` 管来电单（字数 500、图片 4 张、单张 8MB 是**预览值**）；`log.js` 管磁带 / 卡堆与看图窗。`feedback/api.js` 是唯一后端接缝：`verify(code)`、`submit(payload)`。
- **作品页。** `works/page.js` 整理数据、分类陈列架、控制条与碎碎念；`view-cf.js` 展柜（只渲染中间 6 件以内）、`view-grid.js` 瀑布与按月份、`lightbox.js` 大图。
- **漫剧页。** 银幕 + 类型筛选（三档常显，没作品的档位置灰）+ 胶片条 + 当前作品介绍。放映窗：关灯、光束、画面从银幕飞过来、视频先倒数 3-2-1 再建 iframe、长图竖向阅读并显示页码。退出、切后台、`pagehide` 时同一刻拆掉播放器与图片。
- **小游戏页。** 每个游戏一块 4×4 墨色方块，空位用纸面纹理小方块补满；数量变化时棋盘自动加高重排。方块可拖（松手弹回）、点开星盘面板预览、“重新落下”重播下落动画。`status: ready` 且 `path` 合规才跳转。
- **加载页（计划）。** 见“后续阶段”。

## 后续阶段

### 1. 加载页（下一件要做的事）

站主已定的规则：只在进站时出现、点一下可以跳过、为预加载争取时间、会有多个并随机切换。

建议的实现（已与站主对过方向，动工前再确认一次）：

```
loaders/
  registry.js          注册表：id、名称、css、js、status、权重、可配主题
  <id>/loader.js       只导出 mount(host) / unmount()，不碰页面其他部分
  <id>/loader.css      选择器全部限定在 .slx-load 之下
  _template/           新加载页模板 + README.txt
core/loader.js         挑一个 → 挂上去 → 最短停留 → 最长封顶 → 淡出 → 卸载
```

- 进站一次，站内跳转不再出现；随机但记住上一次，连续两次不重复；可选权重。
- 最短约 600ms、最长约 2.5 秒封顶；点一下（或 Esc）立刻进入。
- 加载页是覆盖层，页面内容照常在 DOM 里；脚本报错或超时直接不显示，绝不把站卡住。
- 动效走 `isSimple()` 降级；文案（站名、`PLAYER 1` 之类）从 `data/site.json` 读。
- 先做引擎 + 一个星空白风格的示例页；等站主给更多参考再“新建文件夹 + 注册表加一行”。
- 站内跳转若要缓存过渡页，另做一个“简单过渡层”，与加载页分开。

## 工作方式约定

1. 一次只推进一个阶段，每阶段要有站主能亲手验收的东西，并写清验收步骤（手机和电脑各看一遍）。

## 沙盒与工具备忘（给新窗口，省时间）

- **没有 Playwright。** 系统里有 Chrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`）与 Edge，可以无头截图。
- **无头 Chrome 与 git push 默认会被沙盒拦。** 原因是沙盒禁止进程间通信与凭据管理器。解决办法是给那一次命令临时放行（`sandbox_permissions: danger-full-access` 并写清理由），每次都需要重新放行。
- **窗口最小宽度约 500px。** 直接 `--window-size=390,844` 截出来的图不可信（内容按更宽的视口排版后被裁切）。做法：页面同源放进一个 390px 宽的 iframe 再截父页面，然后裁掉 390 以外的部分。
- **字体请求会失败。** 沙盒无外网，控制台里的字体加载失败不算页面问题；交付前用真机看字体兜底。
- **`--dump-dom` 在带定时器 / 导航的探测页上会挂住。** 优先用“探测页 + 截图里的文字”来读结果，比 dump-dom 稳。
- **探测页要放在站点根目录**（同源才能操作 iframe），测完删掉，保持 `git status` 干净。
- 仓库：`main` 分支，远端 `https://github.com/bytheshadow/spark-light`；提交信息用中文，写清“改了什么 / 新增什么”，别只写“update”。
